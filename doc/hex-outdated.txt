1. INTRODUCTION                                       *hex-outdated-introduction*

hex-outdated.nvim gives live "are my Hex deps up to date?" feedback for Elixir
`mix.exs`, in the spirit of crates.nvim. As you edit `mix.exs`, the plugin
checks each dependency's declared version requirement against hex.pm: inline
virtual text shows the latest version and status, and non-existent
versions/packages show up as diagnostics.

==============================================================================
2. REQUIREMENTS                                       *hex-outdated-requirements*

- Neovim 0.10+
- `curl` on PATH
- (Recommended) the `elixir` Treesitter parser (`:TSInstall elixir`); without
  it, the plugin falls back to Lua patterns.

Run |:checkhealth| hex-outdated to verify these.

==============================================================================
3. INSTALLATION                                       *hex-outdated-installation*

With lazy.nvim: >lua
    {
      "jpease/hex-outdated.nvim",
      ft = "elixir",
      opts = {},
    }
<
With packer.nvim: >lua
    use({
      "jpease/hex-outdated.nvim",
      config = function()
        require("hex-outdated").setup({})
      end,
    })
<
With mini.deps: >lua
    MiniDeps.add({ source = "jpease/hex-outdated.nvim" })
    require("hex-outdated").setup({})
<
With vim-plug: >vim
    Plug 'jpease/hex-outdated.nvim'
    " after plug#end():
    lua require("hex-outdated").setup({})
<
As a native package (no plugin manager), clone into a `pack/*/start`
directory: >sh
    git clone https://github.com/jpease/hex-outdated.nvim \
      ~/.config/nvim/pack/plugins/start/hex-outdated.nvim
<
then call setup from your init.lua: >lua
    require("hex-outdated").setup({})
<
Every manager other than lazy.nvim's `opts = {}` needs an explicit
`require("hex-outdated").setup({})` call, because the plugin activates entirely
through `setup()`.

==============================================================================
4. USAGE                                                     *hex-outdated-usage*

When you open a `mix.exs`, status appears automatically and updates as you type.

The actions are also plain Lua functions, so you can bind your own keys: >lua
    local hex = require("hex-outdated")
    -- hex.refresh() / hex.toggle() / hex.upgrade() / hex.versions() / hex.open()
    -- hex.info()    / hex.lock()
<
==============================================================================
5. COMMANDS                                               *hex-outdated-commands*

                                                                  *:HexOutdated*
:HexOutdated [{subcommand}]
    Run an action. Bare `:HexOutdated` is the same as `refresh`.

    refresh   Re-fetch, bypassing the cache.
    toggle    Enable/disable the inline display for the current buffer.
    upgrade   Rewrite the requirement under the cursor to the latest published
              version.
    versions  Floating window of active published versions; <CR> inserts the
              selected one, q / <Esc> closes.
    open      Open the package's page on hex.pm in a browser.
    info      Floating detail view (requirement / locked / latest) for the
              dependency under the cursor.
    lock      Toggle the per-buffer lock lens (a `locked X · latest Y` line
              under each dependency).

Selecting a release from `versions` preserves the current requirement
operator: comparison requirements stay comparisons, bare exact versions stay
bare, and `~>` keeps its existing precision (with full prerelease versions
preserved). The plugin excludes retired Hex releases from status calculations
and the popup.

==============================================================================
6. STATUS MEANINGS                                          *hex-outdated-status*

  up_to_date  The requirement already allows the latest stable release.
  upgradable  A newer minor/major exists than your requirement targets.
  outdated    An exact pin (`==`) that is below the latest release.
  invalid     No published version matches the requirement (also a diagnostic).

The plugin leaves Git/path deps unannotated, along with requirements it can't
analyze (combined `and`/`or` clauses).

==============================================================================
7. LOCK CONTEXT                                               *hex-outdated-lock*

By default hex-outdated reads only `mix.exs`. When a `mix.lock` is present it
can also show what is actually locked, kept secondary so the inline
requirement status stays primary:

  - Detail float: `:HexOutdated info` (or press K on a dependency line) shows
    requirement / locked / latest for the dependency under the cursor.
  - Lens: `:HexOutdated lock` toggles a `locked X · latest Y` line under each
    dependency (off by default).
  - Stale-lock diagnostic: a warning when `mix.lock` holds a version that no
    longer satisfies your requirement (e.g. after you tighten it), prompting a
    `mix deps.get`.

All of this no-ops when there is no `mix.lock`. Disable it entirely with
`lock = { enabled = false }`.

8. CONFIGURATION                                    *hex-outdated-configuration*

`setup` merges your options over the defaults: >lua
    require("hex-outdated").setup({
      enabled = true,          -- show status when a mix.exs opens
      auto_update = true,      -- re-analyze on buffer changes
      debounce_ms = 500,       -- delay (milliseconds) before re-analyzing
      api = {
        base_url = "https://hex.pm/api",
        timeout_ms = 5000,    -- invalid/non-positive values use 5000
        max_concurrent = 8,    -- cap on simultaneous curl processes
      },
      lock = {
        enabled = true,          -- read mix.lock when present
        lens = false,            -- locked-version lens; off by default
        stale_diagnostic = true, -- warn when the lock no longer satisfies req
      },
      cache = {
        ttl_seconds = 3600,     -- how long a successful fetch is cached
        error_ttl_seconds = 60, -- how long a failed fetch is cached before retry
      },
      text = {                   -- %s is the latest version
        up_to_date = "✓ %s",
        upgradable = "↑ %s",
        outdated = "↓ %s",
        invalid = "✗ no such version",
        loading = "…",
        error = "fetch error",
        lock_behind = "locked %s · latest %s",
        lock_current = "locked %s · up to date",
      },
      highlight = {              -- highlight group per status
        up_to_date = "HexOutdatedUpToDate",
        upgradable = "HexOutdatedUpgradable",
        outdated = "HexOutdatedOutdated",
        invalid = "HexOutdatedInvalid",
        loading = "HexOutdatedLoading",
        error = "HexOutdatedError",
        lock = "HexOutdatedLock",
        lock_behind = "HexOutdatedLockBehind",
      },
      popup = {
        border = "rounded",    -- any nvim_open_win() border
        max_height = 20,       -- max lines in the versions/info float
        hover_key = "K",       -- see |hex-outdated-keymaps|
      },
      keymaps = {},            -- see |hex-outdated-keymaps|
    })
<
`enabled` sets each buffer's initial display state; `:HexOutdated toggle`
flips it per buffer and the commands work either way.

==============================================================================
9. KEYMAPS                                                *hex-outdated-keymaps*

`popup.hover_key` (default "K") is mapped in every `mix.exs` buffer. On a
dependency line it opens the detail float (`:HexOutdated info`); elsewhere it
falls through to `normal! K` (LSP hover or 'keywordprg'). Set it to another
key, or to `false` to leave K unmapped.

`keymaps` adds buffer-local mappings in `mix.exs` buffers, as action = lhs.
Valid actions are the |:HexOutdated| subcommands: `refresh`, `toggle`,
`upgrade`, `versions`, `open`, `info`, `lock`. Unset by default: >lua
    keymaps = {
      upgrade = "<leader>cu",
      versions = "<leader>cv",
      info = "<leader>ci",
    }
<

12. HOW IT WORKS                                      *hex-outdated-how-it-works*

hex-outdated parses `mix.exs` with Treesitter (Lua-pattern fallback) to find
dependency tuples inside the function referenced by the project's `deps:`
setting (`deps/0` by default). For a composed setting such as
`deps: deps() ++ extra()`, only the leading call or list is read. A Hex
package alias such as
`{:local_app, "~> 2.0", hex: :actual_package}` points the API lookup at the
real package, while the local application name still keys into `mix.lock`. For
each Hex dependency the plugin asynchronously queries
`https://hex.pm/api/packages/:name` (cached), excludes retired releases, then
compares your requirement against the active published versions using Hex
prerelease semantics. The requirement status comes from `mix.exs` alone; the
plugin reads `mix.lock` locally, and only for the optional lock context (see
|hex-outdated-lock|). There is no shelling out to `mix`.
